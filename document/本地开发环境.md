# 本地开发环境

本地开发**完全不依赖云端**：数据库跑在本机，图片存本地磁盘，断网也能开发。
云端 Neon 只在需要「把线上数据拉下来」时才连一次。

---

## 日常使用

```bash
npm run db:start   # 启动本地数据库（约 1 秒）
npm run dev        # 启动网站 → http://localhost:3000
```

结束开发时（可选，关机会自动停）：

```bash
npm run db:stop
```

---

## 全部命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动 Next.js 开发服务器 |
| `npm run db:start` | 启动本地 PostgreSQL（端口 **5433**） |
| `npm run db:stop` | 停止本地 PostgreSQL |
| `npm run db:status` | 查看是否在运行 |
| `npm run db:psql` | 打开 SQL 交互终端 |
| `npm run db:sync` | 把线上 Neon 的数据复制到本地（只读线上，不会写入） |
| `npm run db:sync -- --wipe` | 同上，但先清空本地数据再复制 |
| `npm run db:reset` | 删库重建（之后跑一次 `npm run dev` 打开 /admin 会自动重建表结构） |
| `npm run db:setup` | 初次安装用：初始化 → 启动 → 建库 |

## 环境构成

| 项目 | 本地 | 线上 |
|---|---|---|
| 数据库 | PostgreSQL 18.1 绿色版，`D:\pgsql18`，端口 5433 | Neon（新加坡），PostgreSQL 18.6 |
| 查询延迟 | **0 ms** | 73 ms |
| 图片存储 | 本地磁盘（`BLOB_READ_WRITE_TOKEN` 为空时自动） | Vercel Blob / VPS 磁盘 |
| 表结构 | Payload 启动时自动同步（dev push 模式） | 同左 |

**为什么是 5433**：这台机器上已经有一个常驻的 `postgresql-x64-15` Windows 服务占着 5432，
所以绿色版用 5433，两者互不干扰。改端口：设环境变量 `PG_PORT`。

**绿色版的位置**：`D:\pgsql18`（二进制在 `pgsql\`，数据在 `data\`，日志 `pg.log`）。
不是 Windows 服务，不开机自启，整个目录删掉就等于彻底卸载。
改位置：设环境变量 `PG_HOME`。

## `.env.local` 的两个数据库地址

```ini
# 应用实际使用的库 —— 本地
DATABASE_URI=postgres://postgres@127.0.0.1:5433/brandadagio

# db:sync 的复制来源 —— 线上
REMOTE_DATABASE_URI=postgresql://...@...ap-southeast-1.aws.neon.tech/neondb?sslmode=verify-full
```

`db:sync` 的方向永远是 **REMOTE → DATABASE_URI**。
脚本里有保护：如果 `DATABASE_URI` 看起来是云端地址（含 neon.tech / amazonaws / supabase），
会直接中止，防止误把本地数据写进线上库。

## 常见情况

**想拿到线上最新数据** → `npm run db:start` 后 `npm run db:sync -- --wipe`

**本地数据搞乱了想重来**
```bash
npm run db:reset     # 删库重建
npm run dev          # 打开 http://localhost:3000/admin，表结构自动生成
npm run db:sync      # 拉线上数据
```

**改了 `src/collections/*.ts` 里的字段** → 直接重启 `npm run dev` 即可，
Payload 的 dev push 模式会自动把表结构改成新的，不需要写迁移文件。
（部署到 VPS 前再用 `npx payload migrate:create` 生成正式迁移。）

**启动失败** → 看 `D:\pgsql18\pg.log` 最后几行。
最常见原因是端口被占：`netstat -ano | findstr :5433`。

**换一台电脑**
1. 下载 [PostgreSQL 18 Windows 二进制包](https://get.enterprisedb.com/postgresql/postgresql-18.1-1-windows-x64-binaries.zip)，解压到 `D:\pgsql18`（得到 `D:\pgsql18\pgsql\bin\...`）
2. `npm install`
3. `npm run db:setup`
4. `npm run dev` → 打开 `/admin` 让表结构生成
5. `npm run db:sync`

## 部署到 VPS 时要改什么

本地这套和 VPS 的差别只有三处，到时候改配置即可，代码不用动：

1. `DATABASE_URI` 指向 VPS 上的 PostgreSQL
2. `NEXT_PUBLIC_SERVER_URL` 改成正式域名
3. 表结构改用正式迁移（`payload migrate`），不再用 dev push

`REMOTE_DATABASE_URI` 只是本地开发用的，不需要配到服务器上。
