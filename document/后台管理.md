# 后台管理系统 — 实现方案

> 目标：给 MAISON RESERVE 站点增加一个后台，让运营人员**每天上架/下架商品、管理库存与查定申请**。
> 技术前提：现有站点为 **Next.js 14（App Router）+ Supabase + Vercel**，本方案完全复用这套栈，不引入新服务器。

---

## 1. 需求范围

后台每天要处理的核心事项：

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | **商品上架** | 新建商品：填名称/品牌/规格/价格/成色/拠点，上传多张图片 |
| P0 | **商品列表管理** | 列表查看、搜索、筛选（状态/分类），编辑、删除 |
| P0 | **上架/下架** | 一键切换 `status`（available ⇄ draft/sold） |
| P0 | **图片上传** | 拖拽上传到 Supabase Storage，支持多图、排序、删除 |
| P1 | **精选开关** | 切换 `is_featured`（首页「会员限定/精选」展示） |
| P1 | **查定申请管理** | 查看 `sell_requests`，改状态、填鉴定价格 |
| P1 | **咨询/请求查看** | 查看 `inquiries` |
| P2 | 数据概览 | 今日上架数、在售数、待处理查定数 |
| P2 | 操作日志 | 谁在何时改了什么（审计） |

## 2. 方案对比与推荐

| 方案 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| **A. 同一 Next.js 应用内自建 `/admin`（★推荐）** | 与现有站点同仓库/同部署；复用 Supabase Auth 与 RLS；工作流可完全按「每日上架」定制；无额外费用 | 需要自己写 CRUD 页面 | **本项目首选** |
| B. Supabase Studio（官方后台） | 零开发，建完表即可用 | 面向开发者、非运营友好；无图片上传工作流；直接暴露数据库；无法定制流程 | 仅作**过渡/应急**录入 |
| C. Refine / React-Admin 等管理框架 | CRUD 脚手架快 | 额外依赖与学习成本；UI 风格与站点割裂 | 后台功能非常庞大时再考虑 |
| D. Retool / Appsmith / Directus（低代码） | 拖拽搭后台快 | 又多一个系统与账号；数据/权限两地维护；长期成本 | 团队多、需求杂时 |

**推荐：方案 A**——在现有 Next.js 项目里新增受保护的 `/admin` 区域。
理由：单一代码库、单次 Vercel 部署、共享登录态与 Supabase 权限，最贴合「每天快速上架几件商品」的实际操作。
**过渡期**可先用 **Supabase Studio 的 Table Editor** 手动录入商品，等 `/admin` 做好再切换——两者操作的是同一张 `products` 表，无缝衔接。

## 3. 整体架构

```
┌─────────────────────────── 同一个 Next.js 项目 ───────────────────────────┐
│                                                                            │
│   前台（公开）                          后台（受保护 /admin）              │
│   ├─ /            首页                   ├─ /admin/login     登录          │
│   ├─ /shop        商品列表               ├─ /admin          概览          │
│   └─ /shop/[id]   商品详情               ├─ /admin/products 商品管理       │
│                                          │   ├─ /new         新建上架      │
│                                          │   └─ /[id]/edit   编辑          │
│                                          └─ /admin/requests 查定申请       │
│                                                                            │
│   middleware.ts  ── 拦截 /admin/*，校验登录态 + admin 角色                 │
│   Server Actions ── 商品增删改、状态切换（服务端执行，带鉴权）            │
└────────────────────────────────────────────┬───────────────────────────────┘
                                              │
                              ┌───────────────┴───────────────┐
                              ▼                               ▼
                   Supabase Auth（登录）          Supabase Postgres + Storage
                   + profiles.role='admin'        products / sell_requests
                   + RLS 行级安全（双保险）        product-images 存储桶
```

**安全双保险**：
1. **前端网关** —— `middleware` 拦住未登录/非管理员，重定向到登录页；
2. **数据库 RLS** —— 即使接口被绕过，Postgres 层的 RLS 策略也只允许 admin 写入。

## 4. 数据库调整（在 Supabase SQL Editor 执行）

在现有 `schema.sql` 基础上**追加**以下内容。

### 4.1 角色表 `profiles`（区分谁是管理员）

```sql
-- 每个登录用户对应一行，role 决定权限
create table if not exists public.profiles (
  id         uuid primary key references auth.users (id) on delete cascade,
  email      text,
  role       text not null default 'customer',   -- customer / staff / admin
  created_at timestamptz default now()
);

alter table public.profiles enable row level security;

-- 本人可读自己的 profile
create policy "profiles self read"
  on public.profiles for select
  using (auth.uid() = id);

-- 注册时自动建 profile（默认 customer）
create or replace function public.handle_new_user()
returns trigger language plpgsql security definer set search_path = public as $$
begin
  insert into public.profiles (id, email) values (new.id, new.email)
  on conflict (id) do nothing;
  return new;
end; $$;

drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.handle_new_user();

-- 判断当前用户是否管理员（RLS 里复用）
create or replace function public.is_admin()
returns boolean language sql stable security definer set search_path = public as $$
  select exists (
    select 1 from public.profiles
    where id = auth.uid() and role in ('admin', 'staff')
  );
$$;
```

> 创建你自己的管理员账号后，执行一次：
> ```sql
> update public.profiles set role = 'admin' where email = '你的邮箱';
> ```

### 4.2 给 `products` 增加管理字段 + 管理员写权限

```sql
-- 上架时间 / 最后修改人，便于「每日上架」排序与审计
alter table public.products add column if not exists published_at timestamptz;
alter table public.products add column if not exists updated_at   timestamptz default now();
alter table public.products add column if not exists sort_weight  int default 0;   -- 手动置顶

-- 前台只看已上架；新增 draft 作为「未上架」草稿态
--   status: draft(草稿/下架) / available(在售) / reserved(保留) / sold(已售)

-- 已有的「products readable」策略改为只暴露非 draft（保持前台不显示草稿）
drop policy if exists "products readable" on public.products;
create policy "products public read"
  on public.products for select
  using (status <> 'draft');

-- 管理员：可读全部（含 draft）
create policy "products admin read"
  on public.products for select
  using (public.is_admin());

-- 管理员：可增改删
create policy "products admin insert"
  on public.products for insert with check (public.is_admin());
create policy "products admin update"
  on public.products for update using (public.is_admin());
create policy "products admin delete"
  on public.products for delete using (public.is_admin());
```

### 4.3 查定申请：管理员可读可改

```sql
create policy "sell_requests admin read"
  on public.sell_requests for select using (public.is_admin());
create policy "sell_requests admin update"
  on public.sell_requests for update using (public.is_admin());

create policy "inquiries admin read"
  on public.inquiries for select using (public.is_admin());
```

### 4.4 图片存储桶（Storage）

在 Supabase Dashboard → Storage 新建 **public bucket**：`product-images`，或用 SQL：

```sql
insert into storage.buckets (id, name, public)
values ('product-images', 'product-images', true)
on conflict (id) do nothing;

-- 公开读；仅管理员可上传/删除
create policy "product-images public read"
  on storage.objects for select
  using (bucket_id = 'product-images');

create policy "product-images admin write"
  on storage.objects for insert
  with check (bucket_id = 'product-images' and public.is_admin());

create policy "product-images admin delete"
  on storage.objects for delete
  using (bucket_id = 'product-images' and public.is_admin());
```

## 5. 认证与路由保护

### 5.1 中间件：刷新会话 + 拦截 `/admin`

`src/middleware.ts`：

```ts
import { type NextRequest, NextResponse } from "next/server";
import { createServerClient } from "@supabase/ssr";

export async function middleware(request: NextRequest) {
  let res = NextResponse.next({ request });

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll: () => request.cookies.getAll(),
        setAll: (list) => {
          list.forEach(({ name, value, options }) =>
            res.cookies.set(name, value, options)
          );
        },
      },
    }
  );

  const { data: { user } } = await supabase.auth.getUser();
  const path = request.nextUrl.pathname;

  // 保护 /admin（登录页除外）
  if (path.startsWith("/admin") && path !== "/admin/login") {
    if (!user) {
      const url = request.nextUrl.clone();
      url.pathname = "/admin/login";
      return NextResponse.redirect(url);
    }
    // 角色校验：非 admin 踢出
    const { data: profile } = await supabase
      .from("profiles").select("role").eq("id", user.id).single();
    if (!profile || !["admin", "staff"].includes(profile.role)) {
      const url = request.nextUrl.clone();
      url.pathname = "/admin/login";
      url.searchParams.set("error", "forbidden");
      return NextResponse.redirect(url);
    }
  }
  return res;
}

export const config = {
  matcher: ["/admin/:path*"],
};
```

## 6. 商品管理页与「每日上架」工作流

### 6.1 页面清单

| 路由 | 作用 |
|------|------|
| `/admin` | 概览：今日上架数、在售数、待处理查定数 |
| `/admin/products` | 商品列表：搜索、按状态/分类筛选、批量上/下架 |
| `/admin/products/new` | 新建并上架商品 |
| `/admin/products/[id]/edit` | 编辑、切换状态与精选、删除 |
| `/admin/requests` | 查定申请列表与处理 |

### 6.2 每日上架标准流程

```
1. 登录 /admin/login
2. 进入 /admin/products/new
3. 填写：名称 / 品牌 / 分类 / 规格 / 成色 / 拠点 / 价格
4. 拖拽上传 3~5 张图片 → 存到 Storage，得到公开 URL 写入 images[]
5. 选择「立即上架(available)」或「存草稿(draft)」
6. 保存 → 前台 /shop 立即出现（ISR 或按需 revalidate）
7. 需要精选的商品：打开 is_featured 开关 → 首页展示
```

### 6.3 服务端写操作（Server Action 示例）

`src/app/admin/products/actions.ts`：

```ts
"use server";

import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";
import { createClient } from "@/lib/supabase/server";

// 说明：这里用「遵守 RLS 的 server 客户端」，写入前 RLS 会校验 is_admin()。
// 中间件已在网关层拦截，RLS 是第二道防线。

export async function createProduct(formData: FormData) {
  const supabase = createClient();

  const payload = {
    name: String(formData.get("name")),
    brand: String(formData.get("brand") ?? ""),
    category: String(formData.get("category") ?? "bag"),
    spec: String(formData.get("spec") ?? ""),
    condition: String(formData.get("condition") ?? "excellent"),
    location: String(formData.get("location") ?? "東京"),
    price: Number(formData.get("price")),
    currency: String(formData.get("currency") ?? "JPY"),
    images: JSON.parse(String(formData.get("images") ?? "[]")), // 上传后拿到的 URL 数组
    status: String(formData.get("status") ?? "available"),
    is_featured: formData.get("is_featured") === "on",
    published_at: new Date().toISOString(),
  };

  const { error } = await supabase.from("products").insert(payload);
  if (error) throw new Error(error.message);

  revalidatePath("/shop");   // 刷新前台列表缓存
  revalidatePath("/");       // 刷新首页
  redirect("/admin/products");
}

// 一键上/下架
export async function setStatus(id: string, status: "available" | "draft" | "sold") {
  const supabase = createClient();
  const { error } = await supabase
    .from("products")
    .update({ status, updated_at: new Date().toISOString() })
    .eq("id", id);
  if (error) throw new Error(error.message);
  revalidatePath("/shop");
  revalidatePath("/admin/products");
}
```

### 6.4 图片上传（客户端组件示例）

`src/components/admin/ImageUploader.tsx`：

```tsx
"use client";
import { useState } from "react";
import { createClient } from "@/lib/supabase/client";

export default function ImageUploader({
  onChange,
}: { onChange: (urls: string[]) => void }) {
  const supabase = createClient();
  const [urls, setUrls] = useState<string[]>([]);

  async function handleFiles(files: FileList) {
    const uploaded: string[] = [];
    for (const file of Array.from(files)) {
      const path = `${crypto.randomUUID()}-${file.name}`;
      const { error } = await supabase.storage
        .from("product-images").upload(path, file, { upsert: false });
      if (error) { alert(error.message); continue; }
      const { data } = supabase.storage.from("product-images").getPublicUrl(path);
      uploaded.push(data.publicUrl);
    }
    const next = [...urls, ...uploaded];
    setUrls(next);
    onChange(next); // 交给表单，随商品一起保存到 images[]
  }

  return (
    <div>
      <input type="file" accept="image/*" multiple
        onChange={(e) => e.target.files && handleFiles(e.target.files)} />
      <div className="mt-3 flex gap-2 flex-wrap">
        {urls.map((u) => <img key={u} src={u} className="h-20 w-20 object-cover" />)}
      </div>
    </div>
  );
}
```

### 6.5 前台读取从演示数据切到 Supabase

`/shop` 与首页把 `src/lib/data.ts` 的静态数组换成查询：

```ts
// 服务端组件里
const supabase = createClient();
const { data: products } = await supabase
  .from("products")
  .select("*")
  .eq("status", "available")
  .order("published_at", { ascending: false });
```

首页精选：`.eq("is_featured", true)`。可配合 `export const revalidate = 60`（ISR）平衡实时性与性能。

## 7. 安全注意事项

- **不要在前台暴露 `SUPABASE_SERVICE_ROLE_KEY`**。它只能用于服务端脚本/受信任的 Server Action，且必须自己先校验 admin 身份。日常 CRUD 用「遵守 RLS 的 server 客户端」即可，靠 RLS 兜底更安全。
- **管理员账号不走公开注册**：在 Dashboard 手动建用户，再手动升级 `role`。前台不放注册管理员的入口。
- **RLS 必须开启**（4.x 已包含）。上线前用非管理员账号验证：确认其无法读写 draft 商品、无法写 products。
- **图片校验**：上传前限制大小/类型（如 ≤5MB、image/*），必要时服务端二次校验。
- 建议给管理员开启 **Supabase 的邮箱 OTP 或 MFA**。

## 8. 实施步骤（Roadmap）

1. **DB 准备**（0.5 天）：执行第 4 节 SQL；建 `product-images` 桶；创建管理员账号并设 role=admin。
2. **鉴权骨架**（0.5 天）：`middleware.ts` + `/admin/login` 登录页 + `/admin` 空壳布局。
3. **商品 CRUD**（1~2 天）：列表页 + 新建/编辑表单 + `ImageUploader` + Server Actions + 上/下架、精选开关。
4. **前台接数据**（0.5 天）：`/shop`、`/shop/[id]`、首页改为读 Supabase；配置 revalidate。
5. **查定申请管理**（0.5 天）：`/admin/requests` 列表 + 改状态/填鉴定价。
6. **打磨**：概览页、搜索筛选、分页、操作日志（P2）。

> 过渡期：第 1 步做完后，即可先用 **Supabase Studio Table Editor** 手动上架商品，不阻塞前台上线。

## 10. 可选加速方案

若后台需求快速膨胀（多角色、复杂审批、批量导入等），可评估：
- **Refine**（`refinedev/refine`）：React 管理框架，官方支持 Supabase 数据源，脚手架化 CRUD。
- **Directus / Appsmith**：低代码后台，直接连同一个 Postgres。
但初期「每日上架几件商品」的场景，**自建 `/admin` 仍是最简单、最内聚的选择**。
